# 本地 HTTP 性能基线

目标是记录冻结服务当前的速度、完整输出成功率和单请求准入的过载行为，
作为后续优化的比较起点。RTX 3060 Laptop 6 GiB 使用 6 GB CPU offload；
这些结果不能代表模型完全驻留生产 GPU 时的性能。

## 固定工作负载

- 运行 `environment/serving-20261014/compose.frozen.json` 指定的原镜像，不重新构建。
- 使用 ep02 的 clip 1、3、14，循环选择；保存原始 manifest 记录与所有输入帧 SHA256。
- 先执行一次 16-token 预热，不计入各阶段的延迟和吞吐量。
- 诊断模式：16-token 上限、`require_json=false`，并发 1、2、4、8、16，各三轮。
- 每轮同时发出 N 个请求，等全部返回再开始下一轮；无重试、无客户端排队。
- 完整任务：并发 1，三个片段各一次，500-token 上限、严格输出校验、600 秒服务端期限。
- 服务沿用 temperature=0、八帧上限、图像像素预算、单活动请求和原有恢复策略。

开始前关闭其他 GPU 计算任务，保持供电和电源模式一致。运行期间不要重启服务、
更新模型或从其他客户端发送推理请求。脚本记录 GPU 全设备指标，其他应用也会影响结果。

```powershell
docker compose -f environment/serving-20261014/compose.frozen.json up -d --no-build
# 等待 /health/ready 返回 200。
python scripts/benchmark_http_serving.py --output-dir evaluation/runs/performance_baseline_20261014
```

输出目录必须不存在。每次复测使用新目录，保留原始结果，不覆盖旧基线。
主机客户端仅使用 Python 标准库，无需安装推理依赖。GPU 采样使用主机 nvidia-smi。

## 结果与口径

`requests.jsonl` 保存逐请求输入、完整响应、状态码与客户端耗时；每次响应立即落盘。
`results.json` 保存配置、输入指纹、预热、分阶段统计和前后健康状态；
`report.md` 提供对照表；`gpu.jsonl` 每约两秒采样利用率、显存、温度和驱动版本。

客户端延迟从发出 HTTP 请求到读取完整响应，包含服务端预处理和输出校验。
P50/P95/P99 只统计 HTTP 200，避免大量快速 429 让推理延迟显得很低；
另外记录所有响应的 P95、状态码分布及非 200 比例。
吞吐量分别为成功请求数 / 阶段总时间、HTTP 200 返回的输出 token 数 / 阶段总时间。
后者包含预处理、HTTP 和校验，并非纯解码速度。502 响应没有 token 计数，
不能推算失败请求消耗的生成吞吐量。

短输出通常是截断 JSON，仅用于同一工作负载下的系统性能比较，不能记为模型质量通过。
完整任务的 502、504 和其他错误必须保留，不能删除后只展示成功请求。
脚本遇到连接失败、503 或504会提前停止，避免尚未恢复的服务污染后续阶段；
中止时已完成请求和阶段仍保留。只有测量完成才标记 `measured`，这不表示完整输出质量达标。

当前准入上限为 1，因此高并发主要测拒绝行为，不是 continuous batching 性能。
每档成功样本很少，报告中的尾延迟只作探索，不可作为 P99 SLO 或最大容量结论。
接口尚未提供流式输出，TTFT/TPOT 不可测，不能用总耗时除 token 数冒充 TPOT。
真实到达速率、长时间稳态和更大样本测试留待后续；先保留此基线再修改调度参数。

## 完整任务实测与结论

| ep02 片段 | 客户端耗时（秒） | HTTP | 结束原因 | 校验问题 |
|---|---:|---:|---|---|
| 1 | 432.823 | 502 | stop | 摘要 38 词，超过 35 词上限 |
| 3 | 525.770 | 502 | stop | 摘要 57 词；三个事件的帧引用格式无效 |
| 14 | 595.870 | 502 | stop | 摘要 74 词，超过 35 词上限 |

三个请求均自然结束，未触发 600 秒超时。严格合规结果为 **0/3**，
因此完整任务合格结果吞吐量为 0，成功延迟分位数为 N/A。
这不意味着推理没有执行；失败请求累计耗时约 1,554.5 秒。
502 响应没有原始生成文本及 token 计数，不能推算完整任务的纯生成吞吐量。

短输出阶段共 93 个请求：15 个 HTTP 200、78 个 HTTP 429；
完整任务阶段另外三个请求均为 502，预热独立且不计入以上数量。
测试报告标记 `measured` 表示测量完成，绝不表示服务质量验收通过。

GPU 共 921 个有效采样，平均利用率 70.04%，峰值显存 5,168 MiB（约 5.05 GiB），
包含预热及整张 GPU 上其他应用的占用。模型加载耗时 117.39 秒，
测试前后实例 ID 相同、模型加载次数 1，结束时活动请求为 0，服务就绪。

`environment-verification.json` 核验通过：运行镜像、包、OS、启动配置、
服务源码与冻结环境一致，13 个模型文件完整 SHA256 一致，GPU/驱动基线一致。
此次未再次校验离线镜像归档。Docker 设置已持久化为 D 盘迁移目录；
镜像和原项目容器已恢复，没有重新构建服务镜像。
